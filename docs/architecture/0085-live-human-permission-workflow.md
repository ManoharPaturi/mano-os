# Installed human GUI, native broker and TTY PAM workflow

The early headless GTK fixture retains synthetic replies for deliberate slow-response
and stale-window tests. It does not prove the integrated production transport.
A separate disposable-guest witness starts the production Prompt with no injected
submit, status or permission functions after the protected services are installed.
Its observer only publishes the same nonsecret selection/status displayed by GTK.

A private human AT-SPI driver submits a goal and waits for the native acknowledgement.
The Root harness provisions that exact prompt with the existing task factory, then
signals the driver to refresh the task status. The driver opens Permissions, selects
Auto with a120-second/3-grant/10-second-runtime bound, and requests pending review.
It verifies that no authority or password field appeared and captures the visible,
focused pending dialog. The Root harness checks the native view's exact task, terms
and disabled network scope. Cancellation and a wrong password must leave native
new-grant availability false. A separate human-UID controlling PTY then authenticates
with the synthetic guest password; the driver never receives that password.

The pending review text explicitly labels the earlier request acknowledgement;
profile status refresh does not itself refresh the approval record. This prevents
the historical acknowledgement from claiming the approval is still pending.

The GUI refreshes its production native status and must show Auto, exactly3 remaining
new grants and the bounded runtime/remaining time. The effective dialog is captured.
The report binds the prompt/task and hashes both PNGs; acceptance must verify the
hashes and visually inspect the actual pending and effective windows. No paid model
or task execution is requested by this witness. The additional task identity is
removed only after the guest's broker stops during normal harness cleanup.

This is a CI headless workflow, not physical input provenance or physical hardware
validation. No UI confirmation path, policy bypass, host account change or network
access is added to the product.
